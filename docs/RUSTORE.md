# Публикация в RuStore

Материалы и чек-лист для размещения SSH Mobile в RuStore. Публикация выполняется вручную
в консоли RuStore; репозиторий содержит всё необходимое.

### Короткое описание (до 80 символов)

> Безопасный SSH-клиент с терминалом, ключами и проверкой хост-ключей.

### Полное описание

> SSH Mobile — нативный SSH-клиент для Android с полноценным интерактивным терминалом.
>
> Возможности:
> • менеджер серверов: группы, избранное, поиск, быстрый запуск;
> • вход по паролю или приватному ключу (PEM/OpenSSH, passphrase);
> • терминал VT100/xterm: bash, zsh, htop, vim, nano, less;
> • экранные клавиши Ctrl/Alt/Esc/Tab, стрелки, копирование и вставка;
> • несколько одновременных сессий, переподключение после обрыва;
> • проверка host key с SHA-256 fingerprint и предупреждением при смене ключа;
> • шифрование паролей и ключей через Android Keystore;
> • русский и английский интерфейс, тёмная тема.
>
> Приложение не содержит рекламы, аналитики и трекеров. Данные хранятся только на
> устройстве. Для работы нужен собственный SSH-сервер.
>
> Ограничения MVP: SFTP, jump host и port forwarding появятся в следующих версиях.

### Ключевые слова

SSH, терминал, сервер, Linux, администрирование, SSH-клиент, ключи, безопасность

## 3. APK

- Файл: `dist/ssh-mobile-0.1.2-release.apk`
- SHA-256: `A0A0A0303683297B278D8901744AC17AFC2C7DF6469EBDF3478E4D7ED31AF851`
- Размер: 9.66 МБ
- Подпись: RSA-4096, сертификат `CN=SSH Mobile` (SHA-256
  `a67dfa4aa43c2dc6d1799103208d15397a315e90315ce9b970b8cbd348873b63`)
- `minSdk 29`, `targetSdk 35`, поддержка 64-bit ABI (универсальный APK)
- В APK нет тестовых ключей, паролей и приватных данных.
- Keystore и `keystore.properties` **не входят** в репозиторий; для публикации
  используется ваш защищённый keystore.

Сборка:

```bash
./gradlew assembleRelease
# app/build/outputs/apk/release/app-release.apk
```

## 4. Чек-лист перед загрузкой

- [ ] Собрать `assembleRelease` с production-keystore.
- [ ] Увеличить `versionCode` (сейчас 2) при следующем обновлении.
- [ ] Проверить `targetSdk` (35) и 64-bit библиотеки.
- [ ] Убедиться, что в репозитории нет `keystore.properties`, `*.jks`, приватных ключей.
- [ ] Проверить политику конфиденциальности по публичной ссылке.
- [ ] Загрузить иконку 512×512, feature graphic и минимум 2 скриншота.
- [ ] Заполнить описание, категорию, возрастной рейтинг, контакты.
- [ ] Указать, что приложению нужен собственный SSH-сервер (нет демо-аккаунта).
- [ ] Проверить установку APK из консоли на чистом устройстве.
- [ ] Пройти модерацию; при замечаниях обновить `versionCode`, а не перезаписывать APK.

## 5. Возрастной рейтинг и контент

- Нет рекламы, встроенных покупок, подписок и сбора аналитики.
- Нет пользовательского контента, чатов и соцсетей.
- Приложение предоставляет доступ к серверам, которые пользователь добавляет сам;
  ответственность за содержимое серверов лежит на пользователе.
- Терминал может отображать произвольный текст с сервера; приложение не открывает
  ссылки и не исполняет команды автоматически.

## 6. Тестирование модератором

1. Установить APK, запустить — доступен пустой список серверов.
2. «Добавить сервер»: заполнить имя, host, порт, пользователя, пароль или ключ.
3. Подключиться, сверить fingerprint host key, принять.
4. Проверить `echo hello`, `htop`, `vim`, смену раскладки/языка в настройках.
5. Проверить экран «Сессии» и закрытие сессии.
6. Проверить русский/английский язык и тему.

Для проверки нужен тестовый SSH-сервер; публичного демо-сервера нет по соображениям
безопасности. Инструкция по локальному серверу — в `docs/TESTING.md`.

## 7. Что нельзя загружать

- debug APK, APK с тестовыми ключами/паролями;
- `keystore.properties`, `*.jks`, приватные ключи;
- скриншоты с реальными адресами/секретами пользователей;
- сборки без проверки host key.
