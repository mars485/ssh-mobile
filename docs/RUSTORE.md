# Публикация в RuStore

Материалы и пошаговая инструкция для размещения SSH Mobile в RuStore. Сама публикация
выполняется в консоли RuStore — репозиторий содержит всё, что туда загружается:
подписанный APK, графику, тексты карточки и политику конфиденциальности.

## 0. Что готово и что нужно от вас

| Готово в репозитории | Нужно подготовить вручную |
|---|---|
| APK 0.1.2 (versionCode 3), подписан release-ключом | Аккаунт разработчика RuStore ([console.rustore.ru](https://console.rustore.ru)) |
| Иконка 512×512, изображение для карточки 1024×500 | E-mail поддержки (обязательное поле карточки) |
| 3 скриншота 1080×2412 / 1080×2400 | Реквизиты/документы, если консоль их запросит |
| Тексты карточки — `store/listing-ru.md` | — |
| Политика конфиденциальности — `docs/PRIVACY.md` (опубликована) | — |

Требования к типу аккаунта (физлицо / самозанятый / ИП / ООО) зависят от статуса
разработчика и меняются — уточняйте при регистрации. Для бесплатного приложения без
встроенных покупок платежные реквизиты не нужны.

## 1. Публикация: пошагово

1. Войдите в [консоль RuStore](https://console.rustore.ru) под аккаунтом разработчика.
2. «Приложения» → «Создать приложение». Укажите название `SSH Mobile` и пакет
   `dev.sshmobile` (пакет после создания изменить нельзя).
3. Откройте приложение → «Версии» → «Загрузить версию», выберите
   `dist/ssh-mobile-0.1.2-release.apk`.
   Консоль проверит подпись и уникальность `versionCode` (здесь — `3`).
4. Дождитесь окончания проверки файла (антивирус/песочница). Обычно минуты; в редких
   случаях проверка занимает до 14 дней.
5. Заполните карточку: тексты копируются из `store/listing-ru.md`
   (короткое описание, полное описание, ключевые слова, «Что нового», комментарий
   модератору).
6. Загрузите графику: `store/icon-512.png`, `store/feature-graphic-1024x500.png`,
   скриншоты из `store/screenshots/`.
7. Укажите страну распространения (Россия), цену (бесплатно), возрастной рейтинг 0+,
   контакты и ссылку на политику конфиденциальности.
8. Отправьте версию на модерацию. Замечания модерации правятся **новой версией** с
   увеличенным `versionCode`, а не перезаписью APK.
9. После публикации установите приложение из RuStore на чистое устройство и проверьте
   вход по паролю и по ключу.

Альтернатива ручной загрузке — RuStore Public API: черновик версии создаётся запросом
`POST /public/v1/application/{packageName}/version`, файл загружается в
`.../version/{versionId}/apk`, затем версия отправляется на модерацию
`.../version/{versionId}/commit`. Нужен Public-Token из консоли; без него загрузка
выполняется через веб-интерфейс.

## 4. APK

- Файл: `dist/ssh-mobile-0.1.2-release.apk`
- SHA-256: `A0A0A0303683297B278D8901744AC17AFC2C7DF6469EBDF3478E4D7ED31AF851`
- Размер: 10 133 592 байт (9.66 МиБ) — с большим запасом до лимита RuStore (5 ГБ)
- `versionCode 3`, `versionName 0.1.2`, `minSdk 29`, `targetSdk 35`
- ABI: `arm64-v8a`, `armeabi-v7a`, `x86`, `x86_64` (универсальный APK)
- Подпись: RSA-4096, `CN=SSH Mobile`, схема APK Signature v2 (для `minSdk 29` этого
  достаточно, v1 не требуется)
- SHA-256 сертификата:
  `a67dfa4aa43c2dc6d1799103208d15397a315e90315ce9b970b8cbd348873b63`
- В APK нет тестовых ключей, паролей и приватных данных; `keystore.properties` и
  `*.jks` в репозиторий не входят.

Тот же APK лежит в `app/build/outputs/apk/release/app-release.apk` (побайтово совпадает
с копией в `dist/`).

### Сборка

```bash
./gradlew assembleRelease
# app/build/outputs/apk/release/app-release.apk
```

### Проверка перед загрузкой

```powershell
$bt = "D:\Tools\android-sdk\build-tools\35.0.0"   # подставьте свой build-tools
& "$bt\apksigner.bat" verify --print-certs dist\ssh-mobile-0.1.2-release.apk
& "$bt\aapt2.exe" dump badging dist\ssh-mobile-0.1.2-release.apk | Select-String "package:|sdkVersion|native-code"
Get-FileHash dist\ssh-mobile-0.1.2-release.apk -Algorithm SHA256
```

Ожидается: `Verifies`, сертификат `CN=SSH Mobile`, `versionCode='3'`,
`targetSdkVersion:'35'`, четыре ABI и хеш, совпадающий с `dist/SHA256SUMS.txt`.

## 6. Возрастной рейтинг и контент

- Нет рекламы, встроенных покупок, подписок и сбора аналитики.
- Нет пользовательского контента, чатов и соцсетей.
- Приложение предоставляет доступ к серверам, которые пользователь добавляет сам;
  ответственность за содержимое серверов лежит на пользователе.
- Терминал может отображать произвольный текст с сервера; приложение не открывает
  ссылки и не исполняет команды автоматически.

## 7. Тестирование модератором

1. Установить APK, запустить — доступен пустой список серверов.
2. «Добавить сервер»: заполнить имя, host, порт, пользователя, пароль или ключ.
3. Подключиться, сверить fingerprint host key, принять.
4. Проверить `echo hello`, `htop`, `vim`, смену раскладки/языка в настройках.
5. Проверить экран «Сессии» и закрытие сессии.
6. Проверить русский/английский язык и тему.

Для проверки нужен тестовый SSH-сервер; публичного демо-сервера нет по соображениям
безопасности. Инструкция по локальному серверу — в `docs/TESTING.md`. Тот же сценарий
в виде готового текста для поля «Комментарий модератору» — в `store/listing-ru.md`.

## 8. Обновление версии

1. Поднять `versionCode` и `versionName` в `app/build.gradle.kts`.
2. Дописать раздел в `CHANGELOG.md`.
3. `./gradlew assembleRelease`, скопировать APK в `dist/` с новым именем.
4. Пересчитать `dist/SHA256SUMS.txt` и обновить хеш/размер в этом файле и в README.
5. Обновить «Что нового» и версию в `store/listing-ru.md`.
6. Загрузить новую версию в RuStore (старую не перезаписывать).

## 9. Что нельзя загружать

- debug APK, APK с тестовыми ключами/паролями;
- `keystore.properties`, `*.jks`, приватные ключи;
- скриншоты с реальными адресами/секретами пользователей;
- сборки без проверки host key.
